COMPOSE01 / 03

One message, two views: building a multipart email

Pair a readable plain-text fallback with rich HTML using MimeKit's BodyBuilder.

6 MIN READRead note ↗

Most email clients can display HTML, but a well-formed message should still make sense as plain text. BodyBuilder creates the multipart structure for you.

var builder = new BodyBuilder {
    TextBody = "Your order is on its way.",
    HtmlBody = "<p>Your order is on its way.</p>"
};
message.Body = builder.ToMessageBody();

MimeKit emits a multipart/alternative body, so clients can choose the representation they support. Set the sender, recipient, and subject on your MimeMessage before assigning the generated body.

PARSE02 / 03

Reading an email without losing its structure

Load a message as a MIME tree, then inspect headers and parts deliberately.

5 MIN READRead note ↗

An email is more than a string with a subject line. MIME messages can contain nested multiparts, alternative bodies, and attached messages. Parse them into a MimeMessage instead of trying to split raw text yourself.

using var stream = File.OpenRead(path);
var message = MimeMessage.Load(stream);

Console.WriteLine(message.Subject);
Console.WriteLine(message.From);

When processing untrusted mail, treat header values and decoded content as input, and apply your own size limits and validation before storing or displaying them.

ATTACHMENTS03 / 03

Attachments are MIME parts, not an afterthought

Understand how filenames and content dispositions shape an attachment.

7 MIN READRead note ↗

Attachments live in the message's MIME tree. With BodyBuilder, adding a file creates the part and its attachment disposition:

var builder = new BodyBuilder {
    TextBody = "The report is attached."
};
builder.Attachments.Add("report.pdf");
message.Body = builder.ToMessageBody();

For incoming messages, inspect each part's content type and disposition instead of trusting a filename alone. Validate filenames before using them on disk, and consider streaming when handling large messages.
